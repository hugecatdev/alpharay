# AlphaRay — фронтенд «Умного кредитного кабинета»

Веб-кабинет предпринимателя и андеррайтера для цифрового кредитного конвейера (хакатон Альфа-Банка). Клиент подбирает продукт, оформляет заявку в мастере из 6 шагов, следит за статусом, отвечает на запросы банка, принимает предложение, подписывает договор и получает деньги — всё внутри продукта. Андеррайтер разбирает очередь ручного рассмотрения и принимает решения.

## Быстрый старт

Весь проект — из корня репозитория:

```bash
docker compose up --build      # http://localhost:8080
```

Для разработки фронтенд ходит в FastAPI-бэкенд (`../backend`, запуск — в его README):

```bash
npm ci
npm run dev          # http://localhost:5173, /api проксируется на VITE_API_BASE_URL (http://localhost:8000)
```

Тестовые учётки — в [`DEMO_ACCOUNTS.txt`](DEMO_ACCOUNTS.txt) и на экране входа: клик по карточке подставляет почту и пароль (отключается `DEMO_ACCOUNTS_ON_LOGIN=false` на бэкенде). Пароль у всех `demo`:

Ещё в демо:
- Кредит на оборудование без счёта не отправится: шаг «Документы» блокируется, бэкенд ответит 422 `equipment_invoice`.
- Если открыть мастер с `?mock_fail=1`, при отправке заявки бэкенд эмулирует сбой БКИ: рассмотрение длится на 4 с дольше, повторный запрос в БКИ виден в истории у андеррайтера.
- Сбросить демо-данные: `POST /api/demo/reset` (если на бэкенде `DEMO_RESET_ENABLED=true`) или удалить файл состояния бэкенда (`DATA_FILE`, в Docker — том `backend-data`).
- Рэй появляется, только если на бэкенде задан ключ LLM (`LLM_API_KEY`); без ключа панели и кнопок «?» нет.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `VITE_API_BASE_URL` | `http://localhost:8000` | куда dev-сервер Vite проксирует `/api` |

Вся бизнес-логика — конвейер, скоринг, обогащение, договор, ассистент — на бэкенде. Фронтенд ходит в API только через `src/api/endpoints/*`; на клиенте остались лишь мгновенные расчёты для интерфейса (платёж при движении ползунков, «впишется ли платёж», предоценка).

## Docker

```bash
docker build -t alpharay-frontend .     # nginx отдаёт статику и проксирует /api на $API_UPSTREAM
docker run -p 8080:80 -e API_UPSTREAM=http://backend:8000 alpharay-frontend
```

Multi-stage: `node:22-alpine` собирает Vite, `nginx:1.27-alpine` отдаёт статику, делает SPA-fallback и проксирует `/api/` на `API_UPSTREAM` через шаблон `nginx.conf`. Версии зафиксированы в `package-lock.json`.

## Проверки

```bash
npm run typecheck    # tsc strict, без any
npm run lint         # eslint, no-explicit-any = error
npm run build
CHROMIUM_PATH=/usr/bin/chromium npm run e2e   # Playwright, сам поднимает бэкенд (../backend/.venv) и vite
```

E2E запускают бэкенд в памяти с `DEMO_RESET_ENABLED=true` и перед каждым тестом сбрасывают демо-данные. Python бэкенда — `BACKEND_PYTHON` (по умолчанию `.venv/bin/python` в `../backend`).

`e2e/scenarios.spec.ts` повторяет чеклист готовности:
- client1: подбор → заявка → одобрение → подписание (с неверным и верным кодом) → зачисление;
- client3 → андеррайтер делает контрпредложение → клиент принимает;
- client4 — отказ с причинами;
- client5 — запрос информации → ответ с документом → повторный прогон → одобрение;
- оборудование без счёта блокирует шаг «Документы»;
- без ключа LLM Рэй скрыт и сценарий проходит формами; с ключом — ассистент отвечает по экрану и подсвечивает элемент.

## Экраны

**Клиент (`/app`)** — слева навигация, по центру рабочая область, справа ассистент:
- **Главная.** Личный кабинет компании, «Нужно финансирование?» с предварительным лимитом, активные заявки, долговая нагрузка, обороты по счёту, уведомления.
- **Новая заявка** — мастер из 6 шагов:
  1. **Продукт:** цель → продукт.
  2. **Сумма и срок:**
     - слайдеры, платёж, переплата;
     - «Сравните сроки» — три варианта срока: платёж, переплата, нагрузка с учётом текущих кредитов, отметка «Оптимально», выбор кликом; помесячный график платежей — под раскрытием;
     - «Впишется ли платёж» — чистый поток по месяцам, уже после текущих платежей, против нового платежа;
     - для овердрафта вместо платежа — проценты при полном использовании лимита, без сравнения сроков и графика; для оборудования — сумма собственного аванса;
     - вероятность одобрения по правилам кабинета с кнопками-исправлениями;
     - обязательный блок «Кредит — это обязательство»: переплата, нагрузка по всем кредитам и запас прочности — на сколько может упасть выручка, прежде чем поток перестанет покрывать новый платёж.
  3. **Компания:** ЕГРЮЛ по ИНН, «Данные верны».
  4. **Финансы:** предзаполнены по выписке счёта.
  5. **Документы:** drag-and-drop, обязательный счёт для оборудования.
  6. **Отправка:** сводка и согласия, включая подтверждение рисков.

  Черновик сохраняется на каждом шаге, к пройденным шагам можно вернуться.
- **Мои заявки, страница заявки.** Таймлайн «Рассмотрение → Решение → Подписание → Зачисление» (живой, опрос каждые 2 с), «Что происходит», «Что требуется от вас» по статусу: дополнить, принять или отклонить предложение, подписать, причины отказа, график платежей. Плюс история событий.
- **Подписание** — внутри кабинета, без SMS: договор, код `4821` в демо, после подписи — автоматическое зачисление.
- **Уведомления**, **Компания**.
- **Нет компании** (client6): вместо кабинета — онбординг: ИНН → поиск в ЕГРЮЛ/ЕГРИП → «Это моя компания». Если ИП или ООО ещё нет — объясняем, что кредит для бизнеса выдаётся только зарегистрированному бизнесу.

**Андеррайтер (`/bank`):**
- очередь с фильтрами и «Взять в работу»;
- карточка: ЕГРЮЛ / ФНС / БКИ, финансы с подсветкой расхождений, документы, история, скоринг с факторами и стоп-факторами, рекомендация системы, четыре типа решения;
- статистика и воронка.

## Что изменено относительно исходного ТЗ и почему

1. **Ассистент Рэй — подсказчик по экрану, а не исполнитель.** Кейс требует, чтобы ИИ не заменял основной сценарий, а LLM были только open-weight. Рэй — агент на бэкенде поверх OpenAI-совместимого API (по умолчанию Groq, `openai/gpt-oss-120b`), провайдер меняется переменными `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`. Поэтому:
   - ассистент не создаёт черновики и не принимает офферы; единственное действие — по прямой просьбе клиента подставить сумму и срок в форму на шаге «Сумма и срок» (`actions` в ответе), дальше клиент сам проверяет и жмёт «Далее»;
   - он видит контекст текущего экрана (`screen`, ключевые цифры) и объясняет термины, расчёты, статусы, причины решений и риски;
   - он может подсветить элемент интерфейса (`hints` → `data-assist`);
   - кнопки «?» у полей и «Спросить ассистента о рисках» отправляют вопрос в чат с контекстом;
   - без ключа LLM бэкенд отдаёт `assistant_enabled=false` — панель и кнопки не рендерятся, весь сценарий работает формами.
2. **Предупреждение о рисках кредита — часть основного сценария.** Блок на шаге «Сумма и срок» показывает переплату, долю платежа в чистом потоке, стресс-сценарий −20% выручки и последствия просрочки. Подтверждение «понимаю риски» — обязательное согласие перед отправкой.
3. **Меньше повторного ввода.** Финансы, предварительный лимит и «впишется ли платёж» строятся по обороту счёта клиента (`GET /company/insights`).
4. **6 шагов вместо 5.** «Продукт» и «Сумма и срок» разделены — так на доске и в мобильном UX-референсе. Сверху мастера — сводка «Продукт · Сумма · Срок · В месяц · Оценка».
5. **Свой UI-кит вместо `@alfalab/core-components`.** Дизайн-референс — AlphaRay: Manrope (OFL), красный `#e82d22`, фон `#F3F4F5`, скругления, крупные числа. Кит Альфы тянет свой шрифт и визуально спорит с референсом. Есть тёмная тема.

Изменения контракта — в [`docs/API_CHANGES.md`](docs/API_CHANGES.md). Типы — `src/api/types.ts`, их зеркало на бэкенде — `backend/app/schemas.py`, сгенерированная схема — `docs/api/openapi.json`.

## Дизайн-правила

Плоская подача в духе Metro: структуру задают сетка, отступы и типографика, а не карточки.

- **Углы.** Информационные области (плашки, тональные блоки, группы, строки списков, секции) — прямые. Всё, что нажимают (кнопки, поля, выбираемые плитки, вкладки, чипы и бейджи), — скругляется. Иконки в плитках — небольшое скругление, как у значков. Исключение — пузыри чата.
- **Линии.** Горизонтальная линия только между крупными секциями. Внутри секции группирует отступ. Вертикальные разделители — между крупными цифрами. В списках — короткие линии с отступом от иконки. Обводок у карточек и панелей нет.
- **Цвет.** Красный — только действия и выбранное. Лайм — «в вашу пользу» (оптимальный срок, погашенная доля, месяцы, где платёж вписывается): заливкой, текст на нём тёмно-оливковый. Янтарный и красный — риски. Фиолетовый — только Рэй.
- **Рамка интерфейса.** Шапка, меню и Рэй — один лёгкий тон (`--chrome`), контент — белый. Если на странице есть вторая закреплённая полоса (сводка мастера), шапка становится непрозрачной: одновременно размывает только один слой.
- **Цифры** крупные, моноширинные, оговорки стоят прямо у цифры («Предварительно», «≈»), без звёздочек и сносок.

```
src/
  api/            client.ts (JWT, 401 → разлогин, таймауты), types.ts, endpoints/*, queryKeys.ts
  app/            App, router, guards (роли), AppShell (Header, Sidebar, панель ассистента)
  features/
    auth/         LoginPage, AuthProvider
    dashboard/    главная: ЛК, лимит, заявки, долговая нагрузка, обороты, уведомления
    application/  ApplicationWizard + steps/ + wizard/ (расчёты, риски, предоценка), ApplicationPage + details/, SignPage, список
    notifications/, company/ (профиль, онбординг без компании — CompanyGate)
    assistant/    AssistantProvider (контекст экрана, сессия), AssistantPanel, AskButton, Markdown
    bank/         очередь, карточка заявки, скоринг, решения, статистика
  shared/         ui/ (кит), lib/ (money, dates, annuity, statusMeta, labels), hooks/
e2e/              Playwright-сценарии (против реального бэкенда)
```
