## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `JWT_SECRET` | dev-значение | ключ подписи JWT |
| `LOG_LEVEL` | `INFO` | уровень логов |
| `LLM_BASE_URL` | `https://api.groq.com/openai/v1` | любой OpenAI-совместимый `/chat/completions` |
| `LLM_API_KEY` (или `GROQ_API_KEY`) | пусто | ключ провайдера; **пусто - Рэй скрыт** |
| `LLM_MODEL` | `openai/gpt-oss-120b` | модель с открытыми весами |
| `LLM_REASONING_EFFORT` | пусто | `low`/`medium`/`high` для reasoning моделей |


## Кредитные правила

Банк проверяет заявку по порядку:

1. Есть серьёзные проблемы (налоговый долг, блокировки, большая просрочка) - отказ.
2. Бизнесу меньше 3 месяцев - отказ.
3. Выручка в анкете не совпадает с ФНС - банк просит подтвердить выручку.
4. Сумма слишком большая - заявку смотрит андеррайтер.
5. Была просрочка больше 30 дней - заявку смотрит андеррайтер.
6. Платить будет тяжело - банк предлагает меньшую сумму или отказывает.
7. Всё остальное решает скоринг: хороший балл - одобрение, средний - андеррайтер, плохой - отказ.

Если БКИ не ответило - заявку смотрит андеррайтер.
## Ассистент Рэй

Рэй - чат-помощник клиента. Работает с любой LLM через OpenAI-совместимый API, 
__нужно задать `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL`.__

- Рэй объясняет экран и может подставить сумму и срок в заявку. Заявки он сам не отправляет.

Примеры провайдеров:

| Провайдер | `LLM_BASE_URL` | `LLM_MODEL` |
|---|---|---|
| Groq | `https://api.groq.com/openai/v1` | `openai/gpt-oss-120b` |
| Ollama (`docker compose --profile ollama up`) | `http://ollama:11434/v1` | `qwen3:8b` |

Для Ollama ключ - любая строка, например `ollama`.

## Кабинет банка

- Андеррайтер (`underwriter@bank.local`) - очередь заявок, проверки, скоринг, решения.
- Руководитель (`admin@bank.local`) - всё то же, плюс дашборд, сотрудники, продукты, кредитная политика и журнал действий.

Клиент видит только итог по заявке, без внутренних этапов и имён сотрудников.
